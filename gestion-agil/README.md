# Gestión ágil del proyecto

## Enfoque

Proponemos Scrum para planificar incrementos del proyecto AgroSugar-IoT y Kanban en GitHub Projects para visualizar el flujo diario de issues y evidencias. El backlog y los sprints de esta carpeta son una **propuesta de organización** construida a partir de la guía, el informe y los archivos del repositorio; no afirman que el equipo haya realizado las ceremonias Scrum.

Scrum encaja con este trabajo porque combina incertidumbre técnica —KVM, k3s, cargas NDVI y Cloud Bursting— con entregas académicas por corte. Cada Sprint debe tener un objetivo, un incremento revisable y una revisión de lo aprendido. Las prioridades, los roles, las estimaciones y las fechas quedan para que el equipo las acuerde.

## Equipo Scrum

Las responsabilidades de Product Owner, Scrum Master y Developers se deben acordar entre los cuatro integrantes al adoptar este proceso. No se asignan nombres en este documento porque los materiales entregados no registran esa decisión.

## Artefactos

- [Visión del producto](vision-producto.md): problema, usuarios y alcance.
- [Product Backlog](backlog-producto.md): historias, criterios de aceptación y estado de evidencia.
- [Propuesta de Sprints](plan-sprints.md): metas y entregables por incremento, sin fechas inventadas.
- [Definition of Done](definition-of-done.md): condiciones de calidad y evidencia.
- [Plantilla de retrospectiva](plantilla-retrospectiva.md): registro de mejoras acordadas.

En `.github/ISSUE_TEMPLATE/` hay plantillas para registrar historias y defectos directamente en GitHub. La [Guía Scrum oficial](https://scrumguides.org/docs/scrumguide/v2020/2020-Scrum-Guide-Spanish-Latin-South-American.pdf) define el marco; este repositorio solo propone cómo aplicarlo al proyecto.
